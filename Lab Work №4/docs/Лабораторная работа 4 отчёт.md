### Метод GET /v1/ElectronicTypes  
Получить список видов электроники с суммой выдачи (в рублях) за их сдачу и названия прикрепленных к ним документов - правил проверки и оценки.  
Список сортируется по возрастанию id возвращаемых видов электроники.  
Если список видов электроники изменится, то возможен пропуск элементов при их постраничном просмотре. Чтобы избежать этого, можно проверять, изменилась ли коллекция в ходе итераций при помощи ETag.  
#### Описание запроса
##### Параметры запроса  
- skip: integer, необязательный, неотрицательное - число пропущенных с начала списка элементов, при его сортировке по id (максимально можно вернуть 100 элементов за запрос, по умолчанию равно 0).  
- maxCount: integer, необязательный, неотрицательное - максимальное число возвращённых с начала списка элементов после пропуска skip, при его сортировке по id (максимально можно вернуть 100 (если maxCount больше 100, то всё равно выдастся только 100 элементов) элементов за запрос, по умолчанию равно 10).  
- select: string, необязательный - список возвращаемых полей объектов через запятую. При пропуске, вернёт все поля, доступные текущему пользователю по его роли (для клиента это поля id,name,ETag,price, для инспектора и администратора к этим полям добавляется поле rule). При указании поля, недоступного текущему пользователю, ответ будет содержать ошибку 403 Forbidden.      
##### Заголовки запроса  
- Authorization: string, обязательный - принимает только значение "Bearer <токен авторизации>". В противном случае, будет возвращён ответ с кодом 401 Unauthorized.  
- If-None-Match: string, необязательный - принимает значение ETag в кавычках. При указании, делает так, что сервер вернёт список только если посланный ETag данной коллекции не совпадает с ETag данной коллекции на сервере (иначе будет ответ с кодом 304 Not Modified).  
- If-Match: string, необязательный - принимает значение ETag в кавычках. При указании, делает так, что сервер вернёт список только если посланный ETag данной коллекции совпадает с ETag данной коллекции на сервере (иначе будет ответ с кодом 412 Precondition Failed).  
##### Тело запроса  
Так как это метод GET, то тело запроса следует оставлять пустым.  
#### Описание ответа  
##### Коды ответа  
- 401 Unauthorized - не предоставлен токен входа в систему, либо токен нерабочий (возможно, токен просрочен)  
- 400 Bad Request - неверный формат заголовков запроса или неверное значение параметров запросов (не целое неотрицательное число в случае skip и maxCount или несуществующее поле объекта в случае select), либо неизвестный параметр запроса, либо запрос не является корректным HTTP запросом    
- 403 Forbidden - в select указаны поля, недоступные для текущего пользователя, в теле ответа вернётся список этих полей.    
- 304 Not Modified - при указании заголовка If-None-Match, если значение заголовка совпадает с ETag данной коллекции на сервере  
- 412 Precondition failed - при указании заголовка If-Match, если значение заголовка не совпадает с ETag данной коллекции на сервере  
- 200 OK - если получилось успешно вернуть требуемые элементы коллекции (возможно, их будет 0, при пустой коллекции или при некоторых параметрах skip и maxCount).  
##### Заголовки ответа  
- Content-Type: string - в случае ответа с кодом 200 OK, равен application/json.
- Content-Length: integer - в случае ответа с телом, содержит длину тела ответа (в байтах).  
- WWW-Authenticate: string - при коде ответа 401 Unauthorized, содержит строку Bearer, указывающую, что нужно авторизоваться и получить токен авторизации для использования метода. Иначе не возвращается.  
- ETag: string - текущий ETag всей коллекции ElectronicTypes на стороне сервера (при ответе с кодом 200. Иначе не возвращается). ETag коллекции представляет собой число, передающееся в виде строки внутри двойных кавычек (напр. "1"), которое инкрементируется на 1 каждый раз, когда происходит изменение или удаление или добавление элемента в коллекции.  
##### Тело ответа  
При коде ответа 200 OK, вернётся JSON объект с 3 полями:  
- count: integer - число возвращённых видов электроники  
- totalCount: integer - суммарное число видов электроники в коллекции  
- items: array - массив с возвращёнными видами электроники.  
  
Каждый элемент в массиве items представляет собой объект JSON с некоторыми из следующих полей (в зависимости от роли пользователя в системе и значения параметра "select"):  
- id: integer - уникальный идентификатор вида электроники (доступно всем авторизованным пользователям)  
- name: string - название вида электроники (доступно всем авторизованным пользователям)  
- ETag: string - текущий ETag данного вида электроники (доступно всем авторизованным пользователям)  
- rule: string - название документа без URL-encoding с правилами проверки и оценки для данного элемента (доступно только ролям "администратор" и "инспектор" системы). Если документ для данного вида электроники отсутствует, то данное поле возвращено не будет  
- price: integer - сумма денег (в рублях), получаемых клиентом за сдачу данного вида электроники (доступно всем авторизованным пользователям). Если сумма для данного вида электроники не указана, то данное поле возвращено не будет  
Иначе, в теле ответа могут содержаться сведения об ошибке, дублирующие или дополняющие код ответа.

### Метод GET /v1/ElectronicTypes/{id}  
Получить вид электроники с суммой выдачи за его сдачу и имя прикреплённого к нему документа - правил проверки и оценки (сумма выдачи за сдачу price и имя прикреплённого документа rule вернутся, только если они присутствуют в системе для этого вида электроники)  
При запросе можно использовать заголовок If-None-Match с указанием ETag, чтобы вернуть вид электроники только в том случае, если он был обновлён.  
ETag вида электроники на сервере увеличивается каждый раз при его изменении (методы для изменения вида электроники пока не реализованы), удалении или добавлении (методы для добавления вида электроники по id пока не реализованы, а при помощи POST будет добавляться всегда вид электроники с id, который до этого никогда не использовался (при помощи автоинкремента)).  
#### Описание запроса  
##### Параметры запроса  
- id: integer - уникальный идентификатор вида электроники  
- select: string, необязательный - список возвращаемых полей вида электроники через запятую. При пропуске, вернёт все поля, доступные текущему пользователю по его роли (для клиента это поля id,name,price,ETag, для инспектора и администратора к этим полям добавляется поле rule). При указании поля, недоступного текущему пользователю, ответ будет содержать ошибку 403 Forbidden.  
##### Заголовки запроса  
- Authorization: string, обязательный - принимает только значение "Bearer <токен авторизации>". В противном случае, будет возвращён ответ с кодом 401 Unauthorized.  
- If-None-Match: string, необязательный - принимает значение ETag в двойных кавычках. При указании, делает так, что сервер вернёт вид электроники только если посланный ETag данного вида электроники не совпадает с ETag данного вида электроники на сервере (иначе будет ответ с кодом 304 Not Modified).  
##### Тело запроса  
Так как это метод GET, то тело запроса следует оставлять пустым.  
#### Описание ответа  
##### Коды ответа  
- 401 Unauthorized - не предоставлен токен входа в систему, либо токен нерабочий (возможно, токен просрочен)  
- 400 Bad Request - неверный формат заголовков запроса или неверное значение параметров запросов (несуществующее поле объекта в случае select), либо неизвестный параметр запроса, либо запрос не является корректным HTTP запросом
- 403 Forbidden - в select указаны поля, недоступные для текущего пользователя, в теле ответа вернётся список этих полей.  
- 404 Not Found - если вид электроники с заданным id не найден на сервере.  
- 304 Not Modified - при указании заголовка If-None-Match, если значение заголовка совпадает с ETag данного вида электроники на сервере  
- 200 OK - если получилось успешно вернуть поля из вида электроники с данным id.  
##### Заголовки ответа  
- Content-Type: string - в случае ответа с кодом 200 OK, равен application/json.
- Content-Length: integer - в случае ответа с телом, содержит длину тела ответа (в байтах).  
- WWW-Authenticate: string - при коде ответа 401 Unauthorized, содержит строку Bearer, указывающую, что нужно авторизоваться и получить токен авторизации для использования метода. Иначе не возвращается.  
- ETag: string - текущий ETag данного вида электроники на стороне сервера (при ответе с кодом 200. Иначе не возвращается). ETag вида электроники представляет собой число, передающееся в виде строки внутри двойных кавычек (напр. "1"), которое инкрементируется на 1 каждый раз, когда происходит изменение или удаление или добавление вида электроники с заданным id.  
##### Тело ответа  
При коде ответа 200 OK, возвращается объект JSON со всеми или несколькими из следующих полей (список возвращаемых полей зависит от роли пользователя и значения параметра select):  
- id: integer - уникальный идентификатор вида электроники (доступно всем авторизованным пользователям)  
- name: string - название вида электроники (доступно всем авторизованным пользователям)
- ETag: string - текущий ETag данного вида электроники (доступно всем авторизованным пользователям), дублирует значение заголовка "ETag"  
- rule: string - название документа без URL-encoding с правилами проверки и оценки для данного элемента (доступно только ролям "администратор" и "инспектор" системы). Если документ для данного вида электроники отсутствует, то данное поле возвращено не будет  
- price: integer - сумма денег (в рублях), получаемых клиентом за сдачу данного вида электроники (доступно всем авторизованным пользователям). Если сумма для данного вида электроники не указана, то данное поле возвращено не будет
Иначе, в теле ответа могут содержаться сведения об ошибке, дублирующие или дополняющие код ответа.

### Метод GET /v1/Rules/{file_name}  
Получить документ с правилами проверки и оценки товаров по его имени file_name.  
При запросе можно использовать заголовок If-None-Match с указанием ETag, чтобы вернуть документ только в том случае, если он был обновлён.  
ETag документа на сервере увеличивается каждый раз при его изменении (например, методом PUT), удалении или добавлении.  
Метод доступен только пользователям с рольями "Администратор" или "Инспектор"
#### Описание запроса  
##### Параметры запроса  
- file_name: string - уникальное название имени документа.  
##### Заголовки запроса  
- Authorization: string, обязательный - принимает только значение "Bearer <токен авторизации>". В противном случае, будет возвращён ответ с кодом 401 Unauthorized.  
- If-None-Match: string, необязательный - принимает значение ETag в двойных кавычках. При указании, делает так, что сервер вернёт документ только если посланный ETag данного документа не совпадает с ETag данного документа на сервере (иначе будет ответ с кодом 304 Not Modified).
##### Тело запроса
Так как это метод GET, то тело запроса следует оставлять пустым.  
#### Описание ответа  
##### Коды ответа  
- 401 Unauthorized - не предоставлен токен входа в систему, либо токен нерабочий (возможно, токен просрочен)  
- 400 Bad Request - неверный формат заголовков запроса или присутствуют неизвестные параметры запроса, либо запрос не является корректным HTTP запросом
- 404 Not Found - если документ правил проверки и оценки товаров с данным именем не найден на сервере.  
- 403 Forbidden - пользователь не имеет прав на получение документов (в случае, если ролью пользователя является "клиент", а не "администратор" или "инспектор")  
- 304 Not Modified - при указании заголовка If-None-Match, если значение заголовка совпадает с ETag данного документа правил проверки и оценки товаров на сервере  
- 200 OK - если получилось успешно вернуть данный документ проверки и оценки товаров из системы.  
##### Заголовки ответа  
- Content-Type: string - в случае ответа с кодом 200 OK, равен MIME-типу получаемого с сервера документа.  
- Content-Length: integer - в случае ответа с телом, размер возвращаемого документа (в байтах)  
- WWW-Authenticate: string - при коде ответа 401 Unauthorized, содержит строку Bearer, указывающую, что нужно авторизоваться и получить токен авторизации для использования метода. Иначе не возвращается.  
- ETag: string - текущий ETag данного документа с правилами проверки и оценки на стороне сервера (при ответе с кодом 200. Иначе не возвращается). ETag документа представляет собой число, передающееся в виде строки внутри двойных кавычек (напр. "1"), которое инкрементируется на 1 каждый раз, когда происходит изменение или удаление или добавление документа правил проверки и оценки с заданным file_name.  
##### Тело ответа  
В теле ответа представлен документ, посланный с сервера (если код ответа 200 OK).  
Если код ответа был не 200 OK, то в теле ответа могут содержаться сведения об ошибке, дублирующие или дополняющие код ответа.

### Метод POST /v1/ElectronicTypes
Добавляет новый вид электроники (вместе с суммой выдачи и именем прикреплённого к нему документа с правилами проверки и оценки) из тела запроса в систему.  
Для обеспечения идемпотентности используется заголовок Idempotency-Key со значением UUID v4, сгенерированный клиентом. Ключ идемпотентности и ответ хранится на сервере 24 часа, в ходе которых на запрос POST /v1/ElectronicTypes с данным ключом будет возвращаться сохранённый на сервере ответ (новый вид электроники при этом создаваться не будет). Закэшированный ответ будет возвращаться (а незакэшированный - кэшироваться) только после успешной авторизации пользователя.  
Данный запрос доступен только пользователям системы с ролью "Администратор".  
#### Описание запроса  
##### Параметры запроса  
Параметры запроса отсутствуют. При попытке передать серверу параметр запроса, сервер вернёт ответ с кодом 400 Bad Request  
##### Заголовки запроса  
- Authorization: string, обязательный - принимает только значение "Bearer <токен авторизации>". В противном случае, будет возвращён ответ с кодом 401 Unauthorized.  
- Idempotency-Key: string (В виде UUIDv4), обязательный - сгенерированный клиентом ключ идемпотентности для данного запроса в формате UUIDv4. Если отсутствует, сервер вернёт ответ с кодом 400 Bad Request.  
- Content-Type: string, обязательный - принимает только значение application/json. В противном случае, будет возвращён ответ с кодом 400 Bad Request.  
- Content-Length: integer, обязательный - принимает значение длины тела запроса в байтах.  В случае указания неправильной длины тела запроса, сервер может неправильно обработать тело запроса и вернуть ошибку 400 Bad Request. В случае указания тела запроса больше 100 000, сервер выдаст ответ с кодом 413 Payload Too Large  
- If-Match: string, необязательный - принимает значение ETag в кавычках. При указании, делает так, что сервер создаст новый вид электроники только если посланный ETag совпадает с ETag коллекции видов электроники на сервере (иначе будет ответ с кодом 412 Precondition Failed).  
##### Тело запроса  
JSON объект с несколькими из следующих полей:  
- name: string, обязательное - название вида электроники  
- price: integer, необязательное - сумма денег (в рублях) за сдачу клиентом данного вида электроники  
- rule: string, необязательное - название документа (без URL-encoding) с правилами проверки и оценки техники
#### Описание ответа  
##### Коды ответа  
- 401 Unauthorized - не предоставлен токен входа в систему, либо токен нерабочий (возможно, токен просрочен).
- 403 Forbidden - при попытке пользователем с ролью "Клиент" или "Инспектор" воспользоваться данным методом.  
- 400 Bad Request - неверный формат заголовков запроса или переданы параметры запроса, либо запрос не является корректным HTTP запросом, либо отсутствует один из заголовков: Idempotency-Key, Content-Type, Content-Length, либо не удалось десериализовать JSON (из-за ill-formed JSON объекта в теле ответа, либо из-за неправильного значения Content-Length).  
- 413 Payload Too Large - тело запроса является слишком длинным (>100 000, определяется по заголовку Content-Length)
- 412 Precondition failed - при указании заголовка If-Match, если значение заголовка не совпадает с ETag данной коллекции на сервере.  
- 422 Unprocessable Entity - если в переданном серверу JSON объекте присутствуют неизвестные поля, либо известные поля имеют неправильный тип (например, строка вместо числа), либо отсутствует обязательный параметр "name", либо указано название документа, которого нет на сервере.  
- 201 Created - если получилось успешно создать требуемый элемент коллекции. В теле ответа, при этом, вернётся созданный элемент коллекции.  
##### Заголовки ответа  
- Content-Type: string - в случае ответа с кодом 201 Created, равен application/json.
- Content-Length: integer - содержит длину тела ответа (в байтах).  
- WWW-Authenticate: string - при коде ответа 401 Unauthorized, содержит строку Bearer, указывающую, что нужно авторизоваться и получить токен авторизации для использования метода. Иначе не возвращается.
- ETag: string - текущий ETag данного вида электроники на стороне сервера (при ответе с кодом 201. Иначе не возвращается). ETag вида электроники представляет собой число, передающееся в виде строки внутри двойных кавычек (напр. "1"), которое инкрементируется на 1 каждый раз, когда происходит изменение или удаление или добавление вида электроники по одному id.  
##### Тело ответа  
В случае успешного создания вида электроники, возвращается JSON объект данного вида электроники со следующими полями:  
- id: integer - уникальный идентификатор вида электроники  
- name: string - название вида электроники  
- ETag: string - текущий ETag данного вида электроники 
- rule: string - название документа без URL-encoding с правилами проверки и оценки для данного элемента (если название документа не было указано в теле запроса, то данное поле возвращено не будет)  
- price: integer - сумма денег (в рублях), получаемых клиентом за сдачу данного вида электроники (если сумма для данного вида электроники не была указана в теле запроса, то данное поле возвращено не будет)
В случае ошибки, в теле может быть указана информация, дополняющая или дублирующая код ответа

### Метод POST /v1/Rules/{file_name}  
Загрузить новый документ с правилами проверки и оценки из тела запроса в систему.  
Данный метод доступен только пользователям системы с ролью "Администратор".  
#### Описание запроса  
##### Параметры запроса  
- file_name: string - название и одновременно уникальный идентификатор загружаемого документа с правилами проверки и оценки.
##### Заголовки запроса
- Authorization: string, обязательный - принимает только значение "Bearer <токен авторизации>". В противном случае, будет возвращён ответ с кодом 401 Unauthorized.  
- Content-Type: string, обязательный - должен содержать MIME-тип загружаемого документа. В противном случае, будет возвращён ответ с кодом 400 Bad Request.  
- Content-Length: integer, обязательный - принимает значение длины тела запроса в байтах.  В случае указания неправильной длины тела запроса, сервер может или не загрузить файл совсем (вернет ответ 400 Bad Request), или загрузить усеченный вариант файла. При значении больше 100 000 000, сервер вернет ответ с кодом 413 Payload Too Large.
##### Тело запроса  
В теле запроса должен передаваться загружаемый документ.  
#### Описание ответа  
##### Коды ответа  
- 401 Unauthorized - не предоставлен токен входа в систему, либо токен нерабочий (возможно, токен просрочен).
- 403 Forbidden - при попытке пользователем с ролью "Клиент" или "Инспектор" воспользоваться данным методом.  
- 400 Bad Request - неверный формат заголовков запроса или переданы параметры запроса (кроме file_name), либо запрос не является корректным HTTP запросом, либо отсутствует один из заголовков: Content-Type, Content-Length.
- 413 Payload Too Large - тело запроса является слишком длинным (>100 000 000, определяется по заголовку Content-Length).  
- 409 Conflict - документ с правилами проверки и оценки с данным названием уже существует на сервере.  
- 201 Created - если получилось успешно загрузить документ с правилами проверки и оценки.  
##### Заголовки ответа  
- Content-Type: string - в случае ответа с кодом 201 Created, равен application/json.  
- Content-Length: integer - содержит длину тела ответа (в байтах).  
- WWW-Authenticate: string - при коде ответа 401 Unauthorized, содержит строку Bearer, указывающую, что нужно авторизоваться и получить токен авторизации для использования метода. Иначе не возвращается.
- ETag: string - текущий ETag созданного документа с правилами проверки и оценки на стороне сервера (при ответе с кодом 201. Иначе не возвращается). ETag документа с правилами проверки и оценки представляет собой число, передающееся в виде строки внутри двойных кавычек (напр. "1"), которое инкрементируется на 1 каждый раз, когда происходит изменение или удаление или добавление документа с правилами проверки и оценки по одному имени файла.
- Location: string - при успешной загрузке документа (код ответа 201), содержит адрес URL страницы с загруженным документом
##### Тело ответа
В случае успешного создания документа с правилами, возвращается JSON объект, содержащий два поля:
- code: integer - код ответа (201)  
- message: string - пояснение по поводу того, что было сделано в ходе выполнения метода ("New document was created on server!")
В случае ошибки, в теле может быть указана информация, дополняющая или дублирующая код ответа

### Метод GET /v1/Rules  
Получить список всех документов с правилами проверки и оценки в системе с их именами и ETag.  
Список сортируется в порядке добавления правила проверки в систему.  
Данным методом могут воспользоваться только пользователи с ролями "Инспектор" или "Администратор"
Если список документов с правилами изменится, то возможен пропуск элементов при их постраничном просмотре. Чтобы избежать этого, можно проверять, изменилась ли коллекция в ходе итераций при помощи ETag.  
#### Описание запроса  
##### Параметры запроса  
- skip: integer, необязательный, неотрицательное - число пропущенных с начала списка элементов, при его сортировке в порядке добавления элементов в систему (максимально можно вернуть 100 элементов за запрос, по умолчанию равно 0).  
- maxCount: integer, необязательный, неотрицательное - максимальное число возвращённых с начала списка элементов после пропуска skip, при его сортировке в порядке добавления элементов в систему (максимально можно вернуть 100 (если maxCount больше 100, то всё равно выдастся только 100 элементов) элементов за запрос, по умолчанию равно 10).  
##### Заголовки запроса  
- Authorization: string, обязательный - принимает только значение "Bearer <токен авторизации>". В противном случае, будет возвращён ответ с кодом 401 Unauthorized.  
- If-None-Match: string, необязательный - принимает значение ETag в кавычках. При указании, делает так, что сервер вернёт список только если посланный ETag данной коллекции не совпадает с ETag данной коллекции на сервере (иначе будет ответ с кодом 304 Not Modified).  
- If-Match: string, необязательный - принимает значение ETag в кавычках. При указании, делает так, что сервер вернёт список только если посланный ETag данной коллекции совпадает с ETag данной коллекции на сервере (иначе будет ответ с кодом 412 Precondition Failed).  
##### Тело запроса  
Так как это метод GET, то тело запроса следует оставлять пустым.  
#### Описание ответа  
##### Коды ответа  
- 401 Unauthorized - не предоставлен токен входа в систему, либо токен нерабочий (возможно, токен просрочен)
- 403 Forbidden - если пользователь с ролью "Клиент" попытался воспользоваться данным методом    
- 400 Bad Request - неверный формат заголовков запроса или неверное значение параметров запросов (не целое неотрицательное число в случае skip и maxCount), либо неизвестный параметр запроса, либо запрос не является корректным HTTP запросом.  
- 304 Not Modified - при указании заголовка If-None-Match, если значение заголовка совпадает с ETag данной коллекции на сервере  
- 412 Precondition failed - при указании заголовка If-Match, если значение заголовка не совпадает с ETag данной коллекции на сервере  
- 200 OK - если получилось успешно вернуть требуемые элементы коллекции (возможно, их будет 0, при пустой коллекции или при некоторых параметрах skip и maxCount).  
##### Заголовки ответа  
- Content-Type: string - в случае ответа с кодом 200 OK, равен application/json.
- Content-Length: integer - в случае ответа с телом, содержит длину тела ответа (в байтах).  
- WWW-Authenticate: string - при коде ответа 401 Unauthorized, содержит строку Bearer, указывающую, что нужно авторизоваться и получить токен авторизации для использования метода. Иначе не возвращается.  
- ETag: string - текущий ETag всей коллекции Rules на стороне сервера (при ответе с кодом 200. Иначе не возвращается). ETag коллекции представляет собой число, передающееся в виде строки внутри двойных кавычек (напр. "1"), которое инкрементируется на 1 каждый раз, когда происходит изменение, удаление или добавление элемента в коллекции.  
##### Тело ответа  
При коде ответа 200 OK, вернётся JSON объект с 3 полями:  
- count: integer - число возвращённых документов с правилами проверки и оценки.  
- totalCount: integer - суммарное число документов с правилами проверки и оценки в коллекции.  
- items: array - список со сведениями о возвращённых документах с правилами проверки и оценки.  
  
Каждый элемент в массиве items представляет собой объект JSON со следующими полями:  
- name: string - название документа с правилами проверки и оценки  
- ETag: string - текущий ETag данного документа с правилами проверки и оценки

### Метод DELETE /v1/Rules/{file_name}  
Удалить документ с правилами проверки и оценки из системы.  
ETag по данному имени файла остается в системе и инкрементируется при удалении.  
Данным методом могут воспользоваться только пользователи с ролью "Администратор".  
#### Описание запроса  
##### Параметры запроса  
- file_name: string - имя удаляемого документа с правилами проверки и оценки  
##### Заголовки запроса  
- Authorization: string, обязательный - принимает только значение "Bearer <токен авторизации>". В противном случае, будет возвращён ответ с кодом 401 Unauthorized.  
- If-None-Match: string, необязательный - принимает значение ETag в кавычках. При указании, делает так, что сервер удалит документ с правилами только если посланный ETag не совпадает с ETag данного документа на сервере (иначе будет ответ с кодом 304 Not Modified).  
- If-Match: string, необязательный - принимает значение ETag в кавычках. При указании, делает так, что сервер удалит документ с правилами только если посланный ETag совпадает с ETag данного документа на сервере (иначе будет ответ с кодом 412 Precondition Failed).  
##### Тело запроса  
Так как это метод DELETE, тело запроса следует оставлять пустым.
#### Описание ответа  
##### Коды ответа  
- 401 Unauthorized - не предоставлен токен входа в систему, либо токен нерабочий (возможно, токен просрочен)  
- 403 Forbidden - пользователь с ролью "Клиент" или "Инспектор" попытался удалить документ с правилами проверки и оценки  
- 400 Bad Request - неверный формат заголовков запроса, либо неизвестный параметр запроса, либо запрос не является корректным HTTP запросом
- 404 Not Found - если документа с данным именем не удалось найти на сервере.  
- 304 Not Modified - при указании заголовка If-None-Match, если значение заголовка совпадает с ETag данного документа на сервере  
- 412 Precondition failed - при указании заголовка If-Match, если значение заголовка не совпадает с ETag данного документа на сервере
- 204 No Content - если получилось успешно удалить документ.  
##### Заголовки ответа  
- Content-Type: string - содержит MIME-тип тела ответа, если оно присутствует (при коде ответа 204 или 304 тело, и, соответственно, данный заголовок, отсутствуют).  
- Content-Length: integer - содержит длину тела ответа (в байтах), если оно присутствует (при коде ответа 204 или 304 тело, и, соответственно, данный заголовок, отсутствуют).  
- WWW-Authenticate: string - при коде ответа 401 Unauthorized, содержит строку Bearer, указывающую, что нужно авторизоваться и получить токен авторизации для использования метода. Иначе не возвращается.  
##### Тело ответа  
При коде ответа 204 No Content, тело ответа будет пустым.   
Иначе, тело ответа может содержать информацию, дублирующию или дополняющую код ответа.

### Метод PUT /v1/Rules/{file_name}  
Заменить документ с правилами проверки и оценки в системе по его имени file_name (или добавить новый, если документа с данным именем нет в системе)  
Данным методом могут воспользоваться только пользователи с ролью "Администратор".  
#### Описание запроса  
##### Параметры запроса  
- file_name: string - имя заменяемого документа с правилами проверки и оценки
##### Заголовки запроса  
- Authorization: string, обязательный - принимает только значение "Bearer <токен авторизации>". В противном случае, будет возвращён ответ с кодом 401 Unauthorized.  
- Content-Type: string, обязательный - должен содержать MIME-тип загружаемого документа. В противном случае, будет возвращён ответ с кодом 400 Bad Request.  
- Content-Length: integer, обязательный - принимает значение длины тела запроса в байтах.  В случае указания неправильной длины тела запроса, сервер может или не загрузить файл совсем (вернет ответ 400 Bad Request), или загрузить усеченный вариант файла. При значении больше 100 000 000, сервер вернет ответ с кодом 413 Payload Too Large.  
##### Тело запроса  
В теле запроса должен передаваться загружаемый документ.  
#### Описание ответа  
##### Коды ответа  
- 401 Unauthorized - не предоставлен токен входа в систему, либо токен нерабочий (возможно, токен просрочен).
- 403 Forbidden - при попытке пользователем с ролью "Клиент" или "Инспектор" воспользоваться данным методом.  
- 400 Bad Request - неверный формат заголовков запроса или переданы параметры запроса (кроме file_name), либо запрос не является корректным HTTP запросом, либо отсутствует один из заголовков: Content-Type, Content-Length.
- 413 Payload Too Large - тело запроса является слишком длинным (>100 000 000, определяется по заголовку Content-Length).  
- 201 Created - если получилось успешно загрузить документ с правилами проверки и оценки с новым именем, которого еще не было в системе.
- 204 No Content - если получилось успешно заменить существующий документ с правилами проверки и оценки.
##### Заголовки ответа  
- Content-Type: string - в случае ответа с кодом 201 Created, равен application/json.  
- Content-Length: integer - в случае ответа с телом, содержит длину тела ответа (в байтах).  
- WWW-Authenticate: string - при коде ответа 401 Unauthorized, содержит строку Bearer, указывающую, что нужно авторизоваться и получить токен авторизации для использования метода. Иначе не возвращается.
- ETag: string - текущий ETag созданного или измененного документа с правилами проверки и оценки на стороне сервера (при ответе с кодом 201 или 204. Иначе не возвращается). ETag документа с правилами проверки и оценки представляет собой число, передающееся в виде строки внутри двойных кавычек (напр. "1"), которое инкрементируется на 1 каждый раз, когда происходит изменение или удаление или добавление документа с правилами проверки и оценки по одному имени файла.
- Location: string - при успешной загрузке документа (код ответа 201), содержит адрес URL страницы с загруженным документом
##### Тело ответа  
В случае успешного создания или изменения документа с правилами, возвращается JSON объект, содержащий два поля:
- code: integer - код ответа (201)  
- message: string - пояснение по поводу того, что было сделано в ходе выполнения метода ("New document was created on server!")
В случае ошибки, в теле может быть указана информация, дополняющая или дублирующая код ответа
