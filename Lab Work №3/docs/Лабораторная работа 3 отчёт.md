## Диаграмма контейнеров  
Диаграмма контейнеров взята из прошлой лабораторной работы:  
<img width="2021" height="991" alt="изображение" src="https://github.com/user-attachments/assets/17a19145-4753-476a-b75a-0176d0274ad9" />  
### Основные элементы диаграммы:  
- Пользовательский интерфейс клиента - веб-страница, открываемая клиентом в его веб-браузере
- Пользовательский интерфейс инспектора - веб-страница, открываемая инспектором в его веб-браузере
- Пользовательский интерфейс администратора - веб-страница, открываемая администратором в его веб-браузере
- Users - микросервис, содержащий в себе БД с пользователями и БД с сессиями, отвечает за регистрацию новых клиентов, вход пользователей в систему и проверку правомерности запросов от пользователей
- CollectionPoints - микросервис, содержащий в себе БД с точками сдачи техники (магазинами и киосками), отвечает за работу с точками сдачи техники
- ElectronicTypes - микросервис, содержащий в себе БД с видами техники для сдачи (и выплатами, за их сдачу, а также с правилами их приёмки и оценки). Отвечает за работу с видами техники для сдачи
- DoneDeals - микросервис, содержащий в себе БД со сданными экземплярами техники (и оценкой их стоимости от инспектора, а также содержит информацию - вывел ли за этот экземпляр техники клиент деньги или нет). Отвечает за работу со сданными экземплярами техники и вывод денег за них.  
## Диаграмма компонентов контейнера Users  
Диаграмма компонентов контейнера Users взята из прошлой лабораторной работы:

### Основные элементы диаграммы:  
- База данных сессий - база данных, хранящая в себе сессии пользователей с указанием времени их начала и ID пользователя (из БД пользователей), начавших эту сессию
- База данных пользователей - база данных, хранящая в себе пользователей с их логинами, хэшем пароля, адресом электронной почты и типом (клиент, инспектор, администратор)
- Sessions - модуль для создания новых сессий и проверки актуальности всех других. Отвечает за проверку правомерности запросов, вошедших в остальные контейнеры системы
- UsersModule - модуль для регистрации новых клиентов, или для авторизации пользователей по их логину и паролю  
- MailModule - модуль для отправки сообщений клиенту на почту для её подтверждения для регистрации
  
## Диаграмма последовательностей  
Диаграмма последовательностей для варианта использования "регистрация в системе":  
<img width="2327" height="644" alt="изображение" src="https://github.com/user-attachments/assets/0c020bc5-0fb2-4617-b040-01f42466cbef" />  
На данной диаграмме сначала клиент вводит в пользовательский интерфейс логин, пароль и почту для регистрации. Этот запрос в конечном итоге приводит к посылке клиенту письма на электронную почту со ссылкой для подтверждения её.  
При переходе клиента по ссылке на электронной почте, его почта подтверждается и данные о его аккаунте записывается в БД пользователей.  
## Модель БД  
В качестве БД для создания по ней модели в виде диаграммы БД была выбрана БД пользователей. Несмотря на то, в ходе выполнения прошлых работ подразумевалось, что она состоит только из 2 сущностей (Users и Roles), по заданию в диаграмме классов нужно минимум 5 сущностей, поэтому в диаграмму были добавлены ещё 3 сущности (Cities, Countries и Languages).  
<img width="517" height="684" alt="изображение" src="https://github.com/user-attachments/assets/3775e82d-a197-4449-9c99-20e2fbe5adfe" />

  
Краткое описание сущностей и атрибутов в них представлено ниже:  
### Сущность Users - пользователи системы  
- Атрибут id - уникальный идентификатор пользователя  
- Атрибут cityId - ссылка на запись из таблицы Cities - населённый пункт, который указал пользователь как свой в системе
- Атрибут roleId - ссылка на запись из таблицы Roles - роль пользователя в системе
- Атрибут emailAddress - адрес электронной почты, указанный пользователем при регистрации
- Атрибут languageId - ссылка на запись из таблицы Languages - язык, выбранный пользователем в качестве языка интерфейса
- Атрибут passwordHash - хэш пароля пользователя, вычисленный по алгоритму SHA3-512
- Атрибут login - логин пользователя, указанный им при регистрации
### Сущность Roles - роли пользователей в системе
- Атрибут id - уникальный идентификатор роли
- Атрибут name - название роли
### Сущность Cities - населённые пункты пользователей системы
- Атрибут id - уникальный идентификатор населённого пункта  
- Атрибут name - название населённого пункта
- Атрибут country - ссылка на запись из таблицы Countries - страна, где находится данный населённый пункт
- Атрибут latitude - широта населённого пункта
- Атрибут longitude - долгота населённого пункта
### Сущность Countries - страны, которым соответствуют населённые пункты
- Атрибут id - уникальный идентификатор страны
- Атрибут name - название страны
- Атрибут defaultLanguageId - ссылка на запись из таблицы Languages - язык интерфейса, по умолчанию выставленный у пользователей, указавших в качестве населённого пункта тот, который находится в этой стране
### Сущность Languages - языки интерфейса системы
- Атрибут id - уникальный идентификатор языка системы
- Атрибут name - название языка системы
