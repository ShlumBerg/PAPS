## Применение основных принципов разработки  
### DRY
В коде ниже в классе Session подключение к БД пользователей и к БД сессий вынесено в отдельное поле класса, таким образом, не придётся каждый раз писать код для подключения к БД при необходимости что-то с ней сделать:  
```
public class Session {
    private Connection usersDBConnection;
    {
        try {
            usersDBConnection = DriverManager.getConnection("jdbc:postgresql:usersDB?user=postgres&password=postgres&ssl=true");
        } catch (SQLException e) {
            throw new RuntimeException(e);
        }
    }

    private Connection sessionsDBConnection;
    {
        try {
            sessionsDBConnection = DriverManager.getConnection("jdbc:postgresql:sessionsDB?user=postgres&password=postgres&ssl=true");
        } catch (SQLException e) {
            throw new RuntimeException(e);
        }
    }
```
### KISS
В коде ниже в классе Session метод checkIfHasPermission проверяет, имеет ли в рамках текущей сессии пользователь право на выполнение какого-то действия. Метод KISS здесь применяется, так как длина самой функции маленькая (40 строк), и в ней мало точек принятия решений (всего 5 if и catch).  
```
// На вход - Id сесии текущего пользователя и список ролей, которым разрешено данное действие
    public boolean checkIfHasPermission(long sessionId, List<Long> rolesPermitted)
    {
        Long userId=null;
        try(Statement statement = sessionsDBConnection.createStatement();
            //Найти сессию с данным id в БД сессий
            ResultSet sessionRetrieved=statement.executeQuery("SELECT userId, createdAt FROM Sessions WHERE id="+Long.toString(sessionId))) {
            if (!sessionRetrieved.next()) {
                return false; //Данная сессия неактивна - действие выполнить нелья
            }
            Long timeCreatedUnix = sessionRetrieved.getLong("createdAt");
            //Если сессия устарела(прошло более часа с её создания) - удаляем её
            if (timeCreatedUnix + 60 * 60 * 1000 < System.currentTimeMillis()) {
                statement.execute("DELETE FROM Sessions WHERE id=" + Long.toString(sessionId));
                return false; //Сессия устарела - прав нет
            }

            //Получить id пользователя данной сессии
            userId = sessionRetrieved.getLong("userId");
        }
        catch (SQLException e) {
            return false;
        }
        try(
            Statement statement=usersDBConnection.createStatement();
            // Найти роль данного пользователя в БД пользователей
            ResultSet userRetrieved=statement.executeQuery("SELECT roleId FROM Users WHERE id="+userId))
        {
            if(!userRetrieved.next())
            {
                return false; //Нет найденных пользователей
            }
            Long role=userRetrieved.getLong("roleId");
            //Если роль пользователя находится в списке разрешённых - вернет true, иначе вернёт false
            return rolesPermitted.contains(role);
        }
        catch (SQLException e) {
            return false;
        }
    }
```
### YAGNI
Применение принципа YAGNI показано на примере модуля метода register класса UsersClass модуля UsersModule. Он начинает процесс регистрации, получая на вход логин, e-mail и пароль и возвращая true, если было послано письмо для подтверждения почты и окончания регистрации, и false - если произошла ошибка (или послать письмо не удалось из-за исключений, или данная почта или имя пользователя уже есть в БД). В конце также сохраняются данные методом keepRegisterInfoForATime на день, чтобы если пользователь подтвердил почту перейдя по ссылке, была возможность записать запись о нём в БД.  
Непосредственно принцип YAGNI здесь заключается только в том, что метод делает только то, что от него требуется - то есть, проверяет, корректна ли регистрация данного пользователя, хэширует пароль, передаёт управление методу mailSender.sendLetter (он отправляет письмо на электронную почту и создаёт ссылку для подтверждения), передаёт управление методу keepRegisterInfoForATime для временного сохранения сведений о пользователе, и возвращает ответ - послалось ли сообщение для продолжения регистрации. Метод не реализует нетребуемые вещи, например, он не возвращает сведения о том, по какой конкретно причине регистрация не удалась (это не является важным, важно лишь то, что она не удалась)

                                                                                                      // день, пока пользователь не перейдет по ссылке или день не пройдёт
